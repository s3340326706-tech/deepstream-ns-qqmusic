# Deepstream

Nintendo Switch 上的流媒体音乐播放器。

不读本地文件、不占 SD 卡。搜索、歌单、播放全部走网络，音频只在内存里停留，播完即释放。用你自己的账号 Cookie，不需要在电脑上预先导出歌单，也不需要破解或解密任何东西。

> 当前版本 **v0.9.5**（2026-10-21）· 适配 Atmosphère / 固件 23.0.0 · 只测过真实机器，不保证模拟器

---

## 它能做什么

| | 说明 |
|---|---|
| **首页** | 「正在播放」大卡 + 我的歌单 / 播放队列 / 搜索 / 设置四个入口，副标题带实时数字 |
| **搜索** | 关键字搜歌，结果直接可播 |
| **歌单** | 自动同步你账号下的歌单，点进去就是歌曲列表，支持「播放全部」 |
| **播放队列** | 点任意一首歌，整个列表成为队列；可跳转、可单条删除、删掉正在播的会自动接上下一首 |
| **沉浸播放页** | 点底部封面（或按 Y）整屏展开：封面铺底、大封面、进度与控制；进出不重建界面，所以不会崩 |
| **边下边播** | MP3 / FLAC 边下边听，不用等整首下完；m4a 因容器结构需要先缓冲（见下） |
| **封面与进度** | 封面随歌加载，进度条可拖动跳转 |
| **自定义背景** | SD 卡里放几张图，在设置页点一下换背景 |
| **零磁盘缓存** | 全程没有一个缓存文件，内存缓冲上限 128MB，切歌立刻归还 |
| **双输入** | 触屏和手柄都能完整操作，不是「能点但不好用」的那种 |

## 安装

把文件放到 SD 卡，路径必须一模一样：

```
SD 卡根目录/
└── switch/
    ├── deepstream.nro          ← 主程序，必须
    └── se_sources/
        ├── account.json        ← 你的账号 Cookie，必须自己创建
        ├── qqmusic.json        ← 可选，见下
        └── background/         ← 可选，自定义背景图
```

- **`qqmusic.json` 可以不放。** 音源接口描述已经编进 `deepstream.nro` 了。只有在你想自己改接口时才需要把外部文件放进去——**外部文件优先**。
- 但有三段是**强制以内置为准**的：`search.map`、`playlist_songs.map`、`stream.attempts`。它们属于程序逻辑（接口字段怎么映射成歌名、音质档位怎么拼文件名），不是可调参数；改了会让取流直接失效，所以外部文件里写了也不生效。
- **`account.json` 必须自己放。** 它不是配置，是凭据，相当于账号密码，所以永远不会被打进 nro。
- `background/`、`ui.json`、`deepstream.log` 都是运行时自动创建/生成的。

## 账号：怎么弄到 Cookie

这一步只能你自己做，脚本代劳不了，也不该代劳。

1. 电脑浏览器打开 <https://y.qq.com/> 并登录，随便播一首歌
2. `F12` → **Network** 面板 → 点任意一个请求 → **Request Headers** → 找到 `Cookie:`
3. 复制**整串**（一行，含 `=` 和 `;`，不要换行）
4. 存成 `se_sources/account.json`：

```json
{
  "cookie": "uin=o0123456789; qm_keyst=Q_H_L_...; pgv_pvid=2497825952; qqmusic_key=...; ..."
}
```

文件模板见仓库里的 [`account.example.json`](account.example.json)。

**两个容易踩的坑：**

- **`pgv_pvid` 必须在。** 它就是取流要用的 `guid`。少了它接口不会报错，只是永远返回空地址，表现为「所有歌都放不了」，很难查。
- **Cookie 会过期。** 一般是几周到几个月。哪天突然歌单空了或者全部 404，先重新取一次 Cookie，再怀疑程序。

**这个文件不要提交到任何仓库，不要发给任何人。** 拿到它就等于拿到你的账号。

## 按键

### 手柄

| 按键 | 作用 |
|---|---|
| **L / R**（肩键） | 上一首 / 下一首 |
| **ZL / ZR**（扳机） | 快退 / 快进，单击 ±5 秒；按住连续累加，每秒 ±5 秒 |
| **十字键 ← / →** | 在「首页 → 搜索 → 歌单 → 队列 → 设置」之间循环切页；在歌曲页按 → 先退回歌单列表 |
| **十字键 ↑ / ↓** | 在列表里上下移动光标 |
| **左摇杆** | 移动焦点选歌（和十字上下等效） |
| **A** | 播放 / 暂停；也用作「确认」。焦点停在**正在播放的那首**上时是切换播放暂停，停在别的歌上是播放那首 |
| **B** | 逐层返回：沉浸播放页 → 收起；歌曲页 → 歌单页；其他页 → 首页（在首页按 B 不做任何事，不会退出程序） |
| **Y** | 展开 / 收起沉浸播放页（触摸入口是点底部封面） |
| **X / 摇杆按下** | 暂未分配（已预留，按下去不会有反应也不会报错） |

几点说明：

- **切页只在列表区域生效。** 光标停在顶栏图标或底部控制行时，十字左右是用来在按钮之间移动光标的——这两行按钮本来就是横向排列的，抢掉左右键就没法用手柄选中它们了。
- **ZL/ZR 按住时不会真的每秒跳一次。** 流媒体每次跳转都要重新定位、重新下载，一秒一跳会全程卡在缓冲。现在的行为是：按住时进度条和时钟实时跟着走（看得见目标位置），**松手那一刻真正跳一次**。手感上完全等价，但只发一次请求。
- 单只 Joy-Con 横持时用的是另一套按键映射，那种握法没有十字键——请用 Pro 手柄或掌机模式。

### 触屏

所有按钮、列表行、进度条都能直接点。触摸和手柄走的是同一个动作回调，不存在「手柄能点、触摸不认」的分裂。

## 界面

整体是深色车机风格：纯黑画布、`#17181A` 卡片、`#31C27C` 品牌绿。列表行是圆角卡片，手柄焦点为绿色描边，正在播放那一行左侧有一条绿竖条。

顶栏从左到右：

| 图标 | 作用 |
|---|---|
| ⌂ 首页 | 回到首页（正在播放大卡 + 四个入口） |
| 🔍 放大镜 | 进入搜索页并弹出输入法（在搜索页再点一次可以改关键词） |
| ♪ 音符库 | 进入歌单页；已在歌单里则退回列表 |
| ☰ 队列 | 播放队列 |
| ⟳ 刷新 | 歌单页/歌曲页才出现，重新拉一次数据（60 秒内重复进入不会重复请求） |
| ⚙ 齿轮 | 设置页（更换背景图） |

当前所在页面的图标会变成绿色实心。

底部是迷你播放条：封面、歌名、进度条、播放模式位、上一首 / 播放暂停 / 下一首。**点最左边的封面**会展开沉浸播放页：整屏封面铺底（放大 + 压低透明度 + 上暗下亮的渐变）、左侧 400×400 大封面、右侧歌名与歌手、进度条，以及上一首 / 播放 / 下一首。再点左上角返回按钮或按 B 收起。

沉浸播放页是**浮层**而不是独立页面——进出只切 `visibility`，不重建视图树，所以不会出现「点一下界面就崩」的问题。它开着的时候，方向键被拦住，不会跑到被盖住的列表上。

## 自定义背景

1. 把图片放进 `SD:/switch/se_sources/background/`（目录会自动创建）
2. 支持 `.jpg` `.jpeg` `.png` `.bmp` `.tga`
3. 顶栏齿轮 → 设置页 → 点图片，立即生效
4. 选择会记在 `ui.json`，下次启动保持

图片按「填满屏幕」缩放（保持比例，多余部分裁掉），上面盖了一层上浅下深的压暗层，保证白字在任何图上都读得清——**不是纯黑蒙版**，图本身是看得见的。

想恢复纯色背景，在设置页点「不使用背景图」。图片被删掉或改名时也会自动退回纯色，不会留一块空白。

## 为什么有的歌放不出来

音质按这个顺序尝试，**每一档都必须真正下载成功才算数**：

```
标准(128k MP3) → 标准(AAC/m4a) → 高品质(320k MP3) → 无损(FLAC)
```

状态栏会标出实际用的是哪一档，例如 `标准 · MP3 44100Hz 3MB`。

如果全部失败，提示是「所有音质都取不到文件（HTTP 404）」。

**先说一个已经修掉的坑（v0.9.5 之前）**：QQ 音乐的音频文件是按 `media_mid` 命名的，不是 `songmid`。而歌单接口返回的歌曲数据里没有 `media_mid` 字段，只有 `strMediaMid`；旧版映射写的是「取不到就退回 `songmid`」，于是拿着错的 id 去要文件——**接口不报错**，照样返回一个带签名的完整地址，只是那个文件不存在，一直到最后一步下载才变成 404。实测个人歌单 79 首里有 40 首以上中招，表现正是「明明有版权、不用买、也有标准音质，却放不了」。

v0.9.5 起改为优先用 `strMediaMid`，并且在引擎里把「`media_mid` 等于 `songmid`」也视为未解析，去问一次 `vkey.GetVkeyServer/CgiGetVkey`（只传 songmid，服务器会把真实文件名回给我们）。同批 79 首现在 77 首可直接播放，剩下 2 首是无版权。

**升级后如果仍有个别歌失败**，用仓库里的排查脚本，一眼能分清是「取流路径错」还是「真没权限」：

```bash
python app/tools/probe_stream.py "歌名"
```

它会并列打印按 `songmid` 和按 `media_mid` 两条路的真实 HTTP 状态。

剩下的失败就真的只有三种可能：

1. 这首曲子**没有版权**（区域限制或已下架）
2. 需要**单独购买**数字专辑
3. 你的会员等级不够

这三种都无解，程序不会去绕。**默认从「标准」档开始，也是因为这个**：320k 对大量曲目没有权限，而服务端的表现不是报「没权限」，而是返回一个格式完全正确、文件却不存在的地址——撞上去就是 404。之前默认 320 时的大量 404 报错，大部分来自这里（另一部分就是上面那个 `media_mid` 的问题）。

### m4a 起播慢几秒

QQ 音乐的 m4a 没有做 faststart，目录信息（`moov`）写在文件末尾。流式播放拿不到分帧表，所以只能等整首下完再解析，起播会慢 1~3 秒，状态栏显示「缓冲中: 歌名」。

MP3 / FLAC 没有这个问题，是真正的边下边播。

## 从源码构建

需要 devkitPro（Switch 开发环境）+ CMake + Ninja。

**必须用 devkitPro 自带的 msys2 shell 构建。** 别在 Git Bash / CMD / PowerShell 里直接跑——`C:/devkitPro` 在那个 shell 里是挂载点 `/opt/devkitpro`，用别的 shell 会找不到工具链（报 `aarch64-none-elf-pkg-config: No such file`）。

```bash
C:/devkitPro/msys2/usr/bin/bash.exe -lc '
  cd /c/path/to/nxhomebrew/app &&
  mkdir -p build-nx && cd build-nx &&
  cmake -G Ninja -DPLATFORM_SWITCH=ON -DUSE_DEKO3D=ON .. &&
  ninja deepstream.nro
'
```

产物：`app/build-nx/deepstream.nro`

需要安装的 devkitPro 包（portlibs）：

```bash
pacman -S switch-curl switch-mbedtls switch-flac switch-mpg123 switch-zlib
```

`faad2` 已经以源码形式放在 `third_party/faad2/`，由 CMake 编成静态库，不需要额外安装。

**关于 `lib/borealis`**：这是 UI 框架的上游源码副本（基于 commit `5f08b28`），已随仓库提供，clone 下来就能编。其中**有一处本地修改**，在 `library/lib/platforms/switch/switch_input.cpp`：

> Switch 上 `HidNpadButton_AnyLeft/AnyRight` 同时包含十字键和摇杆，导致按一次十字左会同时产生「切页」和「焦点导航」两个事件。本项目把 `BUTTON_NAV_LEFT/RIGHT` 改成只含摇杆位，十字键单独走 `BUTTON_LEFT/RIGHT`。这是全项目唯一改动第三方库的地方，同步上游时请留意。

`library/lib/extern/SDL` 和 `glfw` 是上游的 submodule，Switch 构建用不到，空着即可。

## 目录结构

```
nxhomebrew/
├── app/                    Switch 应用：界面、播放器、音频引擎
│   ├── src/
│   │   ├── player_activity.cpp      主界面、页面切换、按键、播放调度
│   │   ├── player/audio_engine.cpp 下载线程、解码、重采样、audout 输出
│   │   ├── player/mp4_demux.cpp     m4a/MP4 容器解复用
│   │   └── ui/icons.cpp            图标组件（自绘，触屏+手柄统一）
│   ├── resources/sources/qqmusic.json   打进 romfs 的音源描述
│   └── tools/                      PC 端验证脚本
├── engine_cpp/             音源引擎：配置驱动的接口执行器（搜索/歌单/取流）
├── third_party/faad2/      AAC 解码器（GPL-2.0-or-later，见 THIRD_PARTY_NOTICES）
├── lib/borealis/           UI 框架上游源码（Apache-2.0）
├── account.example.json    账号文件模板
└── THIRD_PARTY_NOTICES.md  第三方组件与许可证
```

**设计上的一条主线**：平台接口不写进 C++。搜索、歌单、取流都由 `qqmusic.json` 里的声明式配置描述（请求长什么样、从返回 JSON 的哪个字段取歌名），引擎负责执行。换一个音源平台，理论上只需要写一份新的配置文件。

## 已知限制

| 限制 | 说明 |
|---|---|
| 歌单最多显示前 200 首 | 更大的歌单会提示，暂未做完整分页 |
| 队列不跨启动保存 | 关掉程序队列就没了 |
| 后台播放不支持 | 退出程序声音就停 |
| 无歌词 | 接口里有，界面没做 |
| 无「我的收藏 / 每日推荐」 | 未实现 |
| 触屏键盘输入 | 用系统输入法，切页时焦点偶尔需要重按一次方向键 |
| 播放模式 | 目前固定顺序播放，循环 / 单曲 / 随机未实现 |
| X 键 / 摇杆按下 | 已预留，未分配功能 |

关于「部分歌曲报 404」：那是 v0.9.5 之前的问题——文件名用错了 id，详见上文「为什么有的歌放不出来」，已经修好。如果你手上还有放不了的歌，先确认版本是 v0.9.5，再用 `app/tools/probe_stream.py` 单独查那一首。

本应用目前还是雏形，属于个人兴趣项目，有空才更新。
